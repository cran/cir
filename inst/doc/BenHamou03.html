Vignette for the cir Package

Using Up-and-Down data from Benhamou et al. (2003)

Assaf Oron

2026-11-08

Overview

I demonstrate the cir package with data from the anesthesiology experiment of Benhamou et al. (2003)1, which used the Up-and-Down (UD) dose-finding design. It was re-analyzed a few years later by Pace and Stylianou (2007).2 Here I re-analyze the dataset yet again, using state-of-the-art Centered Isotonic Regression (CIR),3 the cir package’s core estimator.

Up-and-down data analysis was the original motivation for developing CIR and cir. If you are not familiar with UD designs, an overview for general scientific audiences was recently published by Oron et al. (2022).4 An even more recent overview oriented towards statisticians and data scientists, is available in Oron and Flournoy (2025).5

Despite its UD-related history, cir is useful with any binary-outcome data for which a monotone dose-response relationship is expected, regardless of how that data were obtained. Given \(n\) observation pairs consisting of doses \(x_i, i=1, \ldots, n\) and binary responses \(y_i, i=1, \ldots, n\), CIR estimates the dose-response function \(F(x)\), or in short, just \(F\):

\[ F\equiv F(x) \equiv \Pr\left(Y = 1 \mid X = x \right),\] making no assumptions except for strict monotonicity. While the package default (and our description here) assumes an increasing monotone \(F\), the decreasing case is also accommodated, usually by adding the argument \(dec = TRUE\) to function calls.

The package includes methods for both “forward” estimation of \(F\), i.e., the expected response rate conditional on dose, and “inverse” estimation of \(F^{-1}\), a.k.a. dose-finding. Both estimation directions have quick, user-friendly all-in-one functions, as well as more detailed in-depth functions.

If your interest is mainly in UD data analysis rather than more general dose-response data, then you are strongly encouraged to use the dedicated UD package upndown. It includes wrappers for even simpler, single-command plotting and estimation of UD datasets, using cir package functions with the defaults already dialed onto the UD context. You can download the latest version of that package using remotes::install_github(assaforon/upndown). CRAN also has a copy, which while more stable it would also tend to be a couple of steps behind, as upndown is still relatively new and changing a lot.

The Study in our Example

Benhamou et al. (2003) randomized consenting pregnant patients in labor into two arm of \(n=40\) each, to receive as analgesic either ropivacaine or levobupivacaine. The goal was to estimate each agent’s median effective dose (ED\(_{50}\)) for this condition, and to evaluate whether they differ in same-concentration efficacy by comparing the two estimates. The original study used a “traditional” UD dose-averaging estimation method, concluding that even though levobupivacaine seemed 19% more potent, the difference between ED\(_{50}\)s was not significant. To derive inference about this difference, they apparently used the standard errors of dose averages in a \(t\)-test like manner.

Pace and Stylianou (2007) re-analyzed the data using isotonic regression (IR) and 83% bootstrap confidence intervals (CIs); under certain assumptions, examining whether such CIs overlap is roughly equivalent to rejecting the Null hypothesis with \(\alpha = 0.05.\) 6 They found a larger difference than Benhamou et al.: according to the IR estimates, levobupivacaine was 37% more potent . Furthermore, the difference was deemed statistically significant because the 83% CIs did not overlap.

Here we revisit this experiment yet again. To reduce some confusion, we drop the percent sign from description of doses used (in the original, concentrations were described as percents).

Experimental Trajectories

We do not have the original data table, nor do the original authors have access to it anymore; but we can read the sequence of administered doses off of Benhamou et al.’s Figure 1.

# For brevity, we initially use integers to denote the doses. 

xropi = c(11:9,10:8,9,10,9,10:7,8:11,10:12,11:7,8,7:10,9,8,9,8:10,9,10,9,10)
xlevo = c(11,10,11,10,11:9,10:7,8,7,8:5,6:8,7,8:6,7,6,7,6,7:5,6,7,6:12)

Given knowledge of the UD design’s rules, the responses (\(y\)) can be read off directly from the doses (\(x\)). In this specific case, a positive increment indicates no effectiveness (\(y=0\)), and vice versa. Symbolically, \[y = \left( 1-diff(x) \right) / 2.\] We use this and the DRtrace() constructor utility, to create objects that store doses (converted to their physical units) and responses; as we call them here, the experimental “trace” or trajectory.

library(cir)
bhamou03ropi = DRtrace(x = xropi[-40]/100, y = (1-diff(xropi))/2 )
bhamou03levo = DRtrace(x = xlevo[-40]/100, y = (1-diff(xlevo))/2 )

In the construction above we had to give up the 40th and last observation in each arm, because we only know its dose but not the response. As shown above, entering the data takes no more than 2-3 lines of code. But you can also use .csv file input if preferred, with two columns headed x and y.

DRtrace objects have a native plotting method. By the way, DRtrace() and its plotting method can also accommodate data in which observations were collected in groups or cohorts rather than one-by-one as was done here. See function help for details.

par(mfrow=c(1,2), las=1, mar=c(4,4,4,1)) # image format parameters
doserange = (5:12)/100 # This helps set the same y-axis range and labels

plot(bhamou03ropi, dosevals=doserange, ylab="Concentration (%)", main='Ropivacaine Arm', size = 1.5)
legend('bottomright', legend=c('Effective','Ineffective'), pch=c(19,1), bty='n', cex = 1.2)
plot(bhamou03levo, dosevals=doserange, ylab="Concentration (%)", main='Levobupivacaine Arm', size = 1.5)

The “traditional” estimates in the original articles used some type of average of the doses administered. This is based on the premise that over time, UD designs concentrate these doses roughly symmetrically around the target percentile. Generally speaking, these “traditional” estimates are rather outdated and lack robustness. We recommend CIR as the standard estimator for UD experiments (see e.g., Oron et al. 2022 supplement (pdf link)).

Target-dose estimation via regression is an “Inverse Problem”: we draw a line at the desired \(y\) value (in this case, \(50\%\) or 0.5, marked in purple), and look for the best-fitting \(x\) value. Indeed, statistically the task is described as estimating \(F^{-1}(0.5)\), or more generally \(F^{-1}(\Gamma)\), with \(100\Gamma\) being the target percentile.

With the Ropivacaine arm data (left), there is a relatively clear transition between low-response and high-response regions, so the target seems to lie between concentrations \(0.09\) and \(0.10\). We cannot be very confident of that, given the limited amount of information - but at least there’s a clear candidate.

With Levobupivacaine data (right) the picture is far more murky. Concentrations \(0.07\) and \(0.08\) go above \(50\%\) response, but \(0.09\) and \(0.10\) go back below that level. As we visualize further below, CIR helps clarify that picture via the simplest pooled response-rate averages that makes the overall dose-response curve obey monotonicity.

In any case, CIR estimation of the entire \(F(x)\) curve is only one step away.

quickIsotone(bhamou03ropiRates, target=0.5, adaptiveShrink=TRUE)

Estimating the ED\(_{50}\), a.k.a. the target dose, is done very similarly:

ropiTargetCIR = quickInverse(bhamou03ropiRates, target=0.5, adaptiveShrink=TRUE, conf = 0.95)
ropiTargetCIR 
#   target      point lower95conf upper95conf
# 1    0.5 0.09383622  0.07709167   0.1030728
levoTargetCIR = quickInverse(bhamou03levoRates, target=0.5, adaptiveShrink=TRUE, conf = 0.95)
levoTargetCIR
#   target      point lower95conf upper95conf
# 1    0.5 0.06842105  0.05754698  0.09874464

You can also perform the estimation directly from the raw x, y data; the functions will create a doseResponse object on the fly.

The ratio between our point estimates is 1.37, similar to the Pace-Stylianou IR result. Not too surprising, as the methods are closer to each other than to the original authors’ dose-averaging approach; in particular, both are less affected by starting dose, which played a substantial role in the Levobupivacaine arm.

Other Notes

  • The target-dose estimate appears under the word point: 0.0938 for ropivacaine and 0.0684 for levobupivacaine.
  • We specify the target response-rate as a fraction, via the target argument.
  • Default CIs are 90% rather than 95%, due to the large variability and limited confidence in these typically small-sample experiments. Here we use the conf argument to obtain 95% CIs, which are the more appropriate ones when comparing arms, as explained below.
  • The adaptiveShrink option used in our function calls, implements an empirical correction of the bias induced by adaptive designs, a bias described by Flournoy and Oron (2019).7 This type of bias is induced not just by UD designs, but also by model-based adaptive designs such as the Continual Reassessment Method. It is minimal near the target dose, but flares out to substantial magnitudes in both directions. Because of this bias, we strongly recommend to not estimate any dose that is far removed from the dose-finding design’s designated target, except for exploratory/illustrative purposes. The correction offered in cir serves mostly to provide better CI coverage for the target dose estimate.

Comparing the Two Arms

Having examined the methodology behind the CI-overlap approach (which to be prudent, should have been between 84% CIs rather than 83% CIs), we do not recommend it anymore. Besides its somewhat contrived nature, this method is not robust to deviations from distribution assumptions, or even to sample size. Instead, we recommend the more mainstream approach of calculating the (95%) CI for the difference, and observing whether it contains zero.

To obtain the CI of the difference we use the assumption that CI widths are roughly proportional to the square-roots of the variances, as well as independence between arms, while allowing for asymmetry of CI widths to the left and right of the point estimate:

\[ \begin{array}{rcl} LHW_{diff.} & = & \sqrt{LHW_1^2 + RHW_2^2} \\ RHW_{diff.} & = & \sqrt{RHW_1^2 + LHW_2^2}, \end{array} \] where LHW, RHW denote the left- and right-hand widths respectively, and group 2 is the one whose estimates are being subtracted from group 1. Let us put numbers into these formulae:

lhw_1 = ropiTargetCIR$point - ropiTargetCIR$lower95conf
rhw_1 = ropiTargetCIR$upper95conf - ropiTargetCIR$point 
lhw_2 = levoTargetCIR$point - levoTargetCIR$lower95conf
rhw_2 = levoTargetCIR$upper95conf - levoTargetCIR$point 

lhw = sqrt(lhw_1^2 + rhw_2^2)
rhw = sqrt(lhw_2^2 + rhw_1^2)

## Lower 95% bound of difference 
ropiTargetCIR$point - levoTargetCIR$point - lhw
# [1] -0.009224404
## Lower 95% bound of difference 
ropiTargetCIR$point - levoTargetCIR$point + rhw
# [1] 0.03968259

Somewhat surprisingly, we reach a conclusion similar to the original authors: the 95% CI for the difference contains zero, suggesting no evidence for a difference in potency at the \(\alpha=0.05\) level.

Why the different conclusions from Pace and Stylianou? Our CIs are based on an entirely different approach. Per our repeated examinations over the years, the bootstrap approach they used substantially lacks in coverage. We use an analytical approach based on Morris’ theoretical work on intervals for datasets with monotone dose-response data,8 with some modifications.

By the way, we can use the same quickInverse() function to reproduce the Pace-Stylianou point estimates (but not the CIs, since cir does not implement the bootstrap approach):

PSropiEstimate = quickInverse(bhamou03ropiRates, target=0.5, estfun=oldPAVA, conf=0.95)
PSropiEstimate
#   target      point lower95conf upper95conf
# 1    0.5 0.09287671  0.07845822   0.1036113
PSlevoEstimate = quickInverse(bhamou03levoRates, target=0.5, estfun=oldPAVA, conf=0.95)
PSlevoEstimate
#   target      point lower95conf upper95conf
# 1    0.5 0.06846154  0.05999665  0.09607577

Note the argument that chooses oldPAVA() as estimation function (PAVA is the name of the leading algorithm to produce IR estimates; the default is cirPAVA(), i.e., CIR).

Incidentally, plugging the 95% (rather than 83%) CIs calculated by Pace and Stylianou (2007) into the CI-of-difference formula above, we obtain (-0.005, 0.037). Somewhat narrower than the CIR-derived interval, but yielding the same inference - in contrast with the conclusion they actually reached using the 83% CI overlap approach. Looking more closely at their CIs, both \(LHW_1\) and \(RHW_2\) (which in this case are the two half-widths that determine whether there is an overlap) shrank in the 83% CI version to less than half of their 95% CI magnitude. Under a Normal distribution assumption, the 83% CI would be \(\sim 0.7x\) as wide; only rather unusual distributions reach a \(<0.5x\) ratio.

To end the vignette, we visualize more clearly the CIR (and IR) estimates, and the rationale supporting wider intervals from this dataset.

Visualizing CIR on the Dose-Response Plane

To construct the full estimated \(F(x)\) curves from IR and CIR, we call cir’s “long-form” forward-estimation functions:

ropiCurveIR = oldPAVA(bhamou03ropiRates, full=TRUE)
ropiCurveCIR = cirPAVA(bhamou03ropiRates, target=0.5, adaptiveShrink=TRUE, full=TRUE)
levoCurveIR = oldPAVA(bhamou03levoRates, full=TRUE)
levoCurveCIR = cirPAVA(bhamou03levoRates, target=0.5, adaptiveShrink=TRUE, full=TRUE)

With full=TRUE, each of these returns a list of three doseResponse objects. Here’s one example:

  • $input is the incoming data, and

As can be seen below, in cir this takes quite a bit of coding. In the newer upndown package dedicated to up-and-down designs, most of what you see in the plot can be achieved in a single command via the drplot() utility (which does of course rely on cir functions in the backend).

Notes

  • The 2007 estimates were shifted slightly downward in the plot, to make them visible.

  • Referring back to the “murky” picture around target in the Levobupivacaine dose-response plots, we see that both IR (black dashes) and CIR (solid blue) pool the observations from \(x = 0.08, 0,09, 0.10\) into a single weighted average \(y\) value, which is only slightly higher than the estimate at \(x = 0.07.\) The main difference is that IR creates a flat “stretch” with that pooled \(y\) value, whereas CIR also pools along the \(x\) axis into a single point on the dose-response plane. So both these nonparametric algorithms “convert the murkiness” into concluding (with very limited confidence, given the overall small \(n\)) that \(F(x)\) is very shallow for a long stretch, right above the \(y = 0.5\) target response rate.

  • Prior to cir package version 2.3.0, the estimated slope informing the CI was the same to the right and left of target, and hence CIs were usually near-symmetric (and in this particular example, much shorter). We now estimate different “left” and “right” slopes. To revert to the single-slope version, use the argument slopeRefinement = FALSE in your quickInverse() call.

  • In this demonstration the CIR curves differ from the ordinary IR curves not only in the CIR algorithm that “shrinks” horizontal intervals to single points, but also in the bias correction suggested by Flournoy and Oron (2019) and mentioned earlier. In principle this correction is compatible with both methods, but here we applied it only to CIR, because it did not exist at the time of Pace and Stylianou’s article.
